# 简单函数绘图语言语法分析器的设计与实现

## 一、实验目的

1. **理解语法分析在编译过程中的核心作用**，明确其承接词法分析、输出语法树（或语法正确性判断）的核心职责，掌握“Token 序列 $\rightarrow$ 语法结构验证”的完整流程。
2. **掌握上下文无关文法的设计方法**，能针对简单函数绘图语言的语法规则（函数定义、表达式、绘图指令等），定义无歧义、可推导的产生式。
3. **理解递归下降分析法的原理与实现逻辑**，能将设计的文法转化为对应的递归函数，实现语法分析器的核心框架。
4. **实现词法分析器与语法分析器的衔接**，具备基本的语法错误检测与提示能力（如缺少分号、括号不匹配等）。
5. **培养形式化思维与模块化编程能力**，体会“文法设计 $\rightarrow$ 代码实现 $\rightarrow$ 测试优化”的工程化开发流程。

## 二、实验原理

语法分析是编译过程的第二阶段，其核心任务是基于词法分析输出的 **Token 序列**，根据预定义的上下文无关文法，验证 Token 组合的语法合法性，并构建反映语法结构的语法树。

本实验采用递归下降分析法实现语法分析器，核心原理如下：

1. **上下文无关文法：** 文法由终结符（Token 类型，如关键词、标识符）、非终结符（语法结构，如程序、函数定义、表达式）、开始符号（如程序）和产生式（语法规则）组成，通过产生式定义语法结构的推导规则。
2. **递归下降分析法：** 一种自顶向下的语法分析方法，其核心思想是“非终结符与递归函数一一对应”。每个非终结符对应一个递归函数，函数内部根据产生式的右部，依次匹配对应的 Token 或调用其他非终结符的递归函数，实现语法规则的校验与语法树的构建。
3. **语法错误检测：** 若当前 Token 与产生式预期的 Token 类型不匹配时，触发语法错误，通过明确的错误提示（如“期望分号，实际得到逗号”）定位错误位置。
4. **词法 - 语法衔接：** 语法分析器通过调用词法分析器的 `get_next_token()` 方法获取 Token 序列，维护 `current_token` 变量跟踪当前待匹配 Token，通过 `advance()` 方法移动 Token 指针，实现按顺序匹配。

## 三、实验要求

1. **文法设计：** 针对简单函数绘图语言，设计完整的上下文无关文法，涵盖程序 (Program)、语句列表 (StmtList)、函数定义 (FuncDef)、绘图指令 (PlotStmt)、表达式 (Expr) 等核心语法结构，需处理运算符优先级（幂运算 > 乘除 > 加减）与结合性（幂运算右结合，其余左结合），消除文法二义性与左递归。
2. **代码实现：** 基于递归下降分析法，使用与词法分析器一致的编程语言实现语法分析器，包含 `Parser` 类及核心递归函数（如 `parse_program()`、`parse_func_def()`、`parse_expr()` 等）。
3. **功能要求：**
    * 能正确识别合法的 Token 序列，输出对应的语法树（文本或结构化格式）。
    * 能检测至少 3 类语法错误（如缺少分号、括号不匹配、关键字误用），并给出明确的错误提示。
    * 实现语法分析器与词法分析器的无缝衔接，直接接收词法分析器的 Token 输出作为输入。
4. **测试要求：** 设计至少 5 组测试案例（3 组合法输入、2 组含语法错误输入），验证语法分析器的正确性与健壮性，并记录测试结果。
5. **代码规范：** 代码结构清晰，注释完整，变量命名规范，核心逻辑（如递归匹配、错误处理）需添加详细说明。
